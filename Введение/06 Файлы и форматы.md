# Файлы и форматы

## Цель темы

Понять, что файл хранит не "картинку", "текст" или "музыку" в человеческом смысле, а последовательность байтов, которую нужно правильно интерпретировать по правилам формата.

После этой темы ученик должен уметь:

- объяснить разницу между именем файла, расширением и содержимым файла;
- отличать текстовые файлы от бинарных;
- объяснить, зачем нужен формат файла;
- понимать, почему расширение не всегда гарантирует реальный формат;
- объяснить, что такое кодировка и почему из-за нее появляются "кракозябры";
- приводить примеры текстовых, бинарных и контейнерных форматов;
- понимать, почему некоторые файлы можно открыть в Блокноте, а некоторые нет;
- оценивать размер простых файлов по количеству символов или пикселей.

## Зачем это нужно программисту

Программист постоянно работает с файлами: читает входные данные, сохраняет настройки, открывает изображения, пишет логи, разбирает таблицы, создает архивы, подключает библиотеки и запускает инструменты.

Если не понимать форматы, легко ошибиться:

- программа читает файл как текст, но файл на самом деле бинарный;
- файл называется `.txt`, но внутри лежат данные другого типа;
- текст открыт в неправильной кодировке и выглядит испорченным;
- CSV-файл открывается в таблице не так, как ожидалось;
- изображение переименовали, но оно не стало файлом другого формата;
- архив кажется одним файлом, хотя внутри него лежит много файлов.

Для программирования важно отделять три вещи:

```text
имя файла -> как файл называется
расширение -> подсказка о типе файла
содержимое -> реальные байты внутри файла
```

Программа работает не с иконкой и не с расширением, а с содержимым. Расширение помогает выбрать программу для открытия, но не меняет сами данные.

## Подробное объяснение

В теме [05 Файловая система](<./05 Файловая система.md>) файл рассматривался как именованный объект в папке. Теперь важно посмотреть глубже: что лежит внутри файла.

Файл - это именованный набор данных на носителе. ОС хранит файл как последовательность байтов и сведения о нем: имя, путь, размер, дату изменения, права доступа и другие свойства.

Упрощенная модель:

```text
путь показывает, где файл лежит;
имя показывает, как файл называется;
расширение подсказывает предполагаемый тип;
содержимое состоит из байтов;
формат объясняет, как понимать эти байты.
```

### Содержимое файла

Содержимое файла - это данные внутри файла. Имя файла не является его содержимым.

Например, файл может называться:

```text
photo.txt
```

Но внутри у него могут быть байты PNG-изображения. Тогда имя и расширение будут подсказывать "текст", а реальное содержимое будет изображением.

Переименование меняет имя файла, но не переписывает данные внутри:

```text
image.png -> image.txt
```

После такого переименования картинка не становится текстовым документом. Изменилось только имя, а байты изображения остались теми же.

### Формат файла

Формат файла - это правило, по которому данные записаны внутри файла и должны читаться программой.

Формат отвечает на вопросы:

- какие байты означают служебную информацию;
- где начинаются основные данные;
- как записаны размеры, цвета, символы, звук или таблицы;
- есть ли сжатие;
- какие версии формата поддерживаются;
- какие программы умеют правильно читать этот файл.

Примеры:

| Формат | Что хранит | Как читается |
|---|---|---|
| `.txt` | Обычный текст | Текстовым редактором |
| `.md` | Текст с Markdown-разметкой | Текстовым редактором или Markdown-просмотрщиком |
| `.csv` | Табличные данные в виде текста | Текстовым редактором или табличной программой |
| `.png` | Изображение без потери качества | Просмотрщиком изображений |
| `.jpg` | Сжатое фото | Просмотрщиком изображений |
| `.zip` | Архив с файлами внутри | Архиватором |
| `.exe` | Исполняемая программа Windows | ОС запускает как программу |

Формат - это договоренность. Если программа знает правила формата, она может прочитать файл правильно. Если не знает, она увидит просто набор байтов.

### Расширение файла

Расширение - часть имени файла после последней точки.

Примеры:

| Имя файла | Расширение |
|---|---|
| `notes.txt` | `.txt` |
| `lesson.md` | `.md` |
| `photo.png` | `.png` |
| `archive.zip` | `.zip` |
| `report.final.docx` | `.docx` |

Расширение помогает ОС и пользователю выбрать программу для открытия. Например, файл `.png` обычно открывается просмотрщиком изображений, а `.txt` - текстовым редактором.

Но расширение не доказывает реальный формат. Его можно изменить вручную:

```text
song.mp3 -> song.txt
```

Музыкальный файл не станет текстом. Просто Windows может попытаться открыть его не той программой.

### Связь расширения и программы

В Windows для многих расширений настроена программа по умолчанию.

Например:

- `.txt` может открываться Блокнотом;
- `.png` может открываться приложением "Фотографии";
- `.html` может открываться браузером;
- `.zip` может открываться проводником или архиватором.

Это называется ассоциацией файлов. Она влияет на то, какая программа запустится при двойном щелчке.

Важно: ассоциация не меняет формат. Если назначить Блокнот программой по умолчанию для `.png`, изображение не станет текстом. Блокнот просто попытается показать байты изображения как символы.

### Текстовые файлы

Текстовый файл хранит символы в некоторой кодировке. Его можно открыть в текстовом редакторе и прочитать человеком.

Примеры текстовых форматов:

- `.txt` - простой текст;
- `.md` - Markdown-разметка;
- `.csv` - таблица в текстовом виде;
- `.json` - структурированные данные;
- `.xml` - структурированные данные с тегами;
- `.html` - текстовая разметка веб-страницы;
- `.css` - стили веб-страницы;
- `.ini`, `.yaml`, `.toml` - часто используются для настроек.

Текстовый файл не обязан быть "обычным сочинением". Например, JSON тоже текстовый:

```json
{
  "name": "Student",
  "age": 16
}
```

Человек может прочитать такой файл, а программа может разобрать его по правилам JSON.

### Бинарные файлы

Бинарный файл не предназначен для чтения человеком как обычный текст. В нем байты имеют смысл только по правилам конкретного формата.

Примеры бинарных форматов:

- `.png`, `.jpg`, `.gif` - изображения;
- `.mp3`, `.wav` - звук;
- `.mp4`, `.avi` - видео;
- `.zip`, `.7z`, `.rar` - архивы;
- `.exe`, `.dll` - программы и библиотеки Windows;
- `.pdf`, `.docx`, `.xlsx` - документы сложных форматов.

Если открыть бинарный файл в текстовом редакторе, можно увидеть непонятные символы. Это не означает, что файл "сломался". Просто редактор пытается прочитать байты как текст, хотя они записаны по другим правилам.

### Текстовый и бинарный файл: главное различие

Все файлы в компьютере состоят из байтов. Разница в том, как эти байты принято понимать.

| Признак | Текстовый файл | Бинарный файл |
|---|---|---|
| Можно читать в Блокноте | Обычно да | Обычно нет |
| Основное содержимое | Символы | Байты по правилам формата |
| Примеры | `.txt`, `.md`, `.json`, `.csv` | `.png`, `.jpg`, `.mp3`, `.zip`, `.exe` |
| Ошибка при открытии как текст | Может быть неверная кодировка | Непонятные символы почти неизбежны |
| Удобно хранить в Git | Обычно да | Обычно хуже, особенно большие файлы |

Граница не всегда идеально простая. Например, `.pdf` содержит текст документа, но сам формат обычно бинарный и сложный. Файл `.docx` выглядит как один документ, но технически является контейнером с несколькими внутренними файлами.

### Кодировка

Кодировка - способ записать символы числами и байтами.

Компьютер не хранит букву "А" как настоящую букву. Он хранит число, а кодировка говорит, какой символ этому числу соответствует.

Для английских букв и простых символов долго использовалась кодировка ASCII. В ней базовые символы занимают один байт в обычном файле.

Современный стандарт для текстов - Unicode, а самая распространенная кодировка Unicode - UTF-8. В UTF-8:

- английские буквы и цифры обычно занимают 1 байт;
- многие русские буквы занимают 2 байта;
- некоторые символы других языков и специальные знаки могут занимать больше.

Поэтому количество символов в тексте не всегда равно размеру файла в байтах.

Пример:

```text
hello
```

В UTF-8 это обычно 5 байт.

```text
привет
```

В UTF-8 это обычно больше 6 байт, потому что русские буквы занимают больше одного байта.

### "Кракозябры"

"Кракозябры" появляются, когда текстовый файл читают не в той кодировке.

Например:

1. Файл был сохранен в одной кодировке.
2. Редактор открыл его как будто он записан в другой кодировке.
3. Байты остались теми же, но символы были подобраны неправильно.

Итог: вместо нормального текста пользователь видит набор странных символов.

В современных учебных материалах лучше использовать UTF-8. Это снижает риск проблем при переносе файлов между редакторами и компьютерами.

### Переводы строк

Даже в текстовых файлах есть служебные символы. Они тоже являются частью содержимого файла, но обычно не видны как обычные буквы или цифры.

Например, перевод строки - это не просто "пустое место" между строками. В файле он хранится как один или несколько специальных символов. Текстовый редактор видит эти символы и поэтому начинает следующую строку.

Пример текста:

```text
one
two
```

Внутри файла это можно представить так:

```text
one[перевод строки]two
```

В разных системах исторически использовались разные варианты:

| Система | Обозначение перевода строки |
|---|---|
| Windows | `CRLF` |
| Linux/macOS | `LF` |

Обычный пользователь редко думает об этом, но программист может столкнуться с отличиями при работе с Git, скриптами и файлами настроек. Например, файл может выглядеть одинаково в редакторе, но внутри использовать разные символы перевода строки.

Другой пример невидимого символа - табуляция. На экране она выглядит как большой отступ, но внутри файла хранится как специальный символ табуляции. Его часто обозначают как `TAB` или `\t`.

Пример:

```text
name[TAB]age[TAB]city
```

В редакторе это может выглядеть так:

```text
name    age    city
```

Но пробелы и табуляция - не одно и то же. Несколько пробелов и один символ табуляции могут выглядеть похоже, но внутри файла это разные байты. Поэтому в программировании иногда важно включать отображение невидимых символов в редакторе.

Для вводного курса достаточно понимать: перенос строки, табуляция и некоторые другие служебные символы тоже хранятся в файле как байты, хотя пользователь обычно не видит их напрямую.

### Сигнатура файла

Многие форматы начинаются с узнаваемых байтов. Их часто называют сигнатурой файла или magic bytes.

Сигнатура помогает программе понять, что за файл перед ней. Например, PNG-файл имеет характерное начало. ZIP-архивы тоже имеют узнаваемые первые байты.

Идея такая:

```text
расширение говорит: "похоже, это PNG"
сигнатура внутри файла говорит: "данные действительно начинаются как PNG"
```

Это не единственный способ определить формат, но полезная проверка. Поэтому некоторые программы смотрят не только на расширение, но и на содержимое файла.

### Метаданные

Метаданные - это данные о данных.

Примеры метаданных файла:

- имя файла;
- размер;
- дата создания;
- дата изменения;
- права доступа;
- автор документа;
- размеры изображения;
- длительность аудио или видео;
- модель камеры в фотографии.

Часть метаданных хранит файловая система, а часть может храниться внутри самого файла.

Например, у фотографии могут быть:

- имя и дата изменения, которые показывает ОС;
- ширина и высота, записанные внутри изображения;
- EXIF-данные: модель камеры, дата съемки, настройки камеры.

Метаданные помогают программам показывать сведения о файле без полного ручного разбора пользователем.

### Контейнерные форматы

Контейнерный формат - это формат, внутри которого могут находиться другие данные или даже несколько файлов.

Примеры:

- `.zip` - архив с файлами и папками внутри;
- `.docx` - документ Microsoft Word, который внутри устроен как набор XML-файлов и ресурсов в ZIP-контейнере;
- `.xlsx` - таблица Microsoft Excel с внутренними XML-файлами;
- `.mp4` - контейнер для видео, звука, субтитров и служебных данных.

Контейнер похож на коробку: снаружи это один файл, но внутри может быть сложная структура.

Для программиста это важно: иногда "один файл" на самом деле содержит много частей, и его нужно открывать специальным инструментом или библиотекой.

### Сжатие

Сжатие уменьшает размер данных, если в них есть повторения или закономерности.

Пример хорошо сжимаемых данных:

```text
AAAAAAAAAAAAAAAAAAAAAAAA
```

Вместо хранения каждой буквы отдельно можно хранить идею "много букв A подряд".

Пример плохо сжимаемых данных:

```text
8F 3A 91 C0 7B 22 ...
```

Если данные похожи на случайные или уже были сжаты, уменьшить их размер трудно.

Поэтому:

- текстовые файлы часто хорошо сжимаются;
- BMP-изображения без сжатия могут хорошо сжиматься архиватором;
- JPG, PNG, MP3 и MP4 уже используют собственные способы сжатия;
- ZIP от уже сжатого файла может почти не уменьшиться.

### Размер файла

Размер файла обычно измеряется в байтах, КБ, МБ или ГБ. Подробно единицы разбираются в теме [08 Биты байты и единицы информации](<./08 Биты байты и единицы информации.md>), но для этой темы полезно уметь делать простые оценки.

Пример 1. ASCII-текст:

```text
1000 символов * 1 байт = 1000 байт
```

Пример 2. Несжатое изображение 100 на 100 пикселей, 3 байта на пиксель:

```text
100 * 100 = 10 000 пикселей
10 000 * 3 = 30 000 байт
```

Реальный PNG или JPG может занимать другой размер, потому что в нем есть служебные данные и сжатие.

### Что происходит при открытии файла

Когда пользователь дважды щелкает по файлу, обычно происходит такая цепочка:

```text
1. ОС смотрит на расширение файла.
2. ОС выбирает программу по умолчанию.
3. Программа открывает файл и читает байты.
4. Программа пытается разобрать байты по правилам ожидаемого формата.
5. Если формат понятен, программа показывает содержимое.
6. Если формат не подходит, программа показывает ошибку или непонятные данные.
```

Если файл `.png` открыть просмотрщиком изображений, программа разберет его как картинку. Если тот же файл открыть Блокнотом, Блокнот попробует показать байты как текст, и результат будет непонятным.

### Типичные ошибки

**"Если я поменял расширение, формат изменился."**  
Нет. Переименование меняет имя файла, но не переписывает содержимое по правилам другого формата.

**"Если файл открывается в Блокноте, это обычный текст для человека."**  
Не всегда. Некоторые бинарные файлы могут случайно содержать фрагменты читаемого текста, но основной формат все равно может быть бинарным.

**"Если файл не читается в Блокноте, он испорчен."**  
Не обязательно. Возможно, это нормальный бинарный файл: картинка, архив, музыка или программа.

**"Расширение всегда честно показывает тип файла."**  
Нет. Расширение можно изменить. Поэтому важно смотреть на источник файла, программу открытия и иногда на содержимое.

**"Размер текста всегда равен количеству символов."**  
Нет. В UTF-8 разные символы могут занимать разное количество байтов. Кроме того, в файле есть переводы строк и иногда служебные байты.

**"Архив - это просто папка."**  
Не совсем. Архив может выглядеть как папка в проводнике, но на диске это файл со своим форматом. Чтобы получить содержимое, его нужно распаковать или открыть архиватором.

## Примеры

### Пример 1. Markdown-файл

Файл `lesson.md` - текстовый файл. Его можно открыть в Блокноте и увидеть исходный текст:

```markdown
# Заголовок

Это обычный текст с разметкой Markdown.
```

Markdown-просмотрщик может показать этот же файл красиво: заголовки станут крупнее, списки будут оформлены, ссылки станут кликабельными.

Один и тот же файл можно читать как обычный текст и отображать как форматированный документ.

### Пример 2. PNG-файл открыт как текст

Файл `image.png` - бинарный. Если открыть его текстовым редактором, редактор попытается превратить байты изображения в символы.

Результат будет выглядеть как набор непонятных знаков. Это нормально: данные изображения не предназначены для чтения как обычный текст.

### Пример 3. Переименование не меняет формат

Был файл:

```text
photo.png
```

Его переименовали:

```text
photo.txt
```

Содержимое осталось прежним. Если открыть `photo.txt` в Блокноте, он не станет нормальным текстом. Если открыть его программой, которая умеет распознавать PNG по содержимому, она может все равно понять, что это изображение.

### Пример 4. CSV как текст и как таблица

CSV-файл может выглядеть так:

```csv
name,age,city
Anna,16,Yerevan
Ivan,17,Moscow
```

В текстовом редакторе это просто строки с запятыми. В табличной программе это может отображаться как таблица из трех столбцов.

Файл тот же, но разные программы показывают его по-разному.

### Пример 5. Архив как один файл и набор файлов

Файл `materials.zip` снаружи выглядит как один файл.

Внутри него могут лежать:

```text
lesson-01.md
lesson-02.md
images\diagram.png
tasks\practice.txt
```

Архиватор умеет прочитать структуру ZIP и показать внутренние файлы. Обычный текстовый редактор не покажет архив как понятный список материалов.

## Практика на занятии

1. Создайте текстовый файл `notes.txt` и откройте его в Блокноте.
2. Создайте Markdown-файл `lesson.md` и сравните его с `.txt`.
3. Создайте CSV-файл с 2-3 строками и откройте его как текст и как таблицу.
4. Возьмите изображение и попробуйте открыть его текстовым редактором.
5. Переименуйте копию изображения, изменив расширение на `.txt`. Ответьте, изменилось ли содержимое файла.
6. Переименуйте копию текстового файла, изменив расширение на `.md`. Ответьте, изменился ли формат содержимого.
7. Посмотрите размер нескольких файлов разных типов: `.txt`, `.md`, `.png`, `.jpg`, `.zip`.
8. Найдите у изображения ширину, высоту и размер файла. Сравните реальный размер с простой оценкой `ширина * высота * 3 байта`.
9. Если есть архив `.zip`, откройте его и посмотрите, какие файлы находятся внутри.
10. Откройте один и тот же файл разными программами и сравните, как меняется отображение.
