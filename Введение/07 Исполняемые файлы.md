# Исполняемые файлы

## Цель темы

Понять, что такое исполняемый файл, чем он отличается от документа, что происходит при запуске программы и почему неизвестные исполняемые файлы опасны.

После этой темы ученик должен уметь:

- объяснить разницу между данными и инструкциями;
- отличать открытие документа от запуска программы;
- приводить примеры исполняемых и сценарных файлов Windows;
- понимать, что при запуске файла ОС создает процесс;
- объяснять, почему расширения `.exe`, `.bat`, `.cmd`, `.ps1`, `.msi` требуют осторожности;
- понимать, зачем нужны права администратора и UAC;
- объяснять, почему иконка файла не доказывает его безопасность;
- объяснять, зачем нужны цифровые подписи и проверка источника;
- составлять базовое правило безопасной проверки файла перед запуском.

## Зачем это нужно программисту

Программист постоянно запускает инструменты: редакторы, компиляторы, интерпретаторы, установщики, скрипты, пакетные файлы, тесты и вспомогательные утилиты.

При этом программист работает с большим количеством файлов из разных источников:

- скачанные установщики;
- архивы с проектами;
- скрипты сборки;
- команды из документации;
- исполняемые файлы из папок проекта;
- файлы из папки `Downloads`;
- инструменты, установленные через менеджеры пакетов.

Если не различать документы, данные, программы и сценарии, можно случайно выполнить вредный файл или дать программе больше прав, чем нужно.

Важно понимать:

```text
прочитать файл -> использовать его как данные
выполнить файл -> запустить инструкции из файла
```

Документ обычно открывают в программе. Исполняемый файл сам становится программой или передается специальной программе-оболочке, которая выполняет записанные в нем команды.

## Подробное объяснение

В теме [06 Файлы и форматы](<./06 Файлы и форматы.md>) файл рассматривался как последовательность байтов в определенном формате. Исполняемый файл - особый случай: его содержимое предназначено не просто для чтения, а для выполнения.

### Данные и инструкции

Файл может хранить данные или инструкции.

Данные - это то, что программа читает, показывает или изменяет:

- текст документа;
- таблица;
- изображение;
- звук;
- настройки;
- архив.

Инструкции - это команды, которые компьютер должен выполнить:

- создать файл;
- удалить файл;
- записать данные;
- открыть окно;
- подключиться к сети;
- установить программу;
- запустить другой процесс.

Упрощенно:

```text
документ -> данные для программы
исполняемый файл -> инструкции для ОС, процессора или командной оболочки
```

Это главное различие. Открытие фотографии и запуск программы - разные действия с разным уровнем риска.

### Исполняемый файл

Исполняемый файл - это файл, который ОС или специальная среда может запустить как программу или сценарий.

В Windows самый узнаваемый пример - `.exe`.

Но исполняемые и запускаемые файлы бывают разными:

| Расширение | Что это | Как запускается |
|---|---|---|
| `.exe` | Обычная программа Windows | Напрямую ОС |
| `.msi` | Установочный пакет Windows Installer | Через установщик Windows |
| `.bat` | Командный файл CMD | Через командную оболочку |
| `.cmd` | Командный файл Windows | Через командную оболочку |
| `.ps1` | Сценарий PowerShell | Через PowerShell |
| `.vbs` | Сценарий VBScript | Через Windows Script Host |
| `.js` | Сценарий JavaScript для Windows Script Host или веба | Зависит от среды |
| `.dll` | Библиотека | Обычно загружается другой программой |
| `.lnk` | Ярлык | Ссылается на другой файл или команду |

Не все из этого запускается одинаково. Например, `.dll` обычно не запускают двойным щелчком как обычную программу. Она содержит код, который используют другие программы. А `.lnk` не является программой сам по себе, но может указывать на программу или команду.

### Что происходит при запуске программы

Для пользователя запуск выглядит просто: двойной щелчок по файлу или ввод команды.

Для ОС это последовательность действий:

```text
1. Пользователь запускает файл.
2. ОС определяет, как его запускать.
3. ОС проверяет права доступа и ограничения безопасности.
4. ОС загружает код программы в RAM.
5. ОС создает процесс.
6. Процесс получает память, права и системные ресурсы.
7. CPU начинает выполнять инструкции программы.
8. Программа может читать файлы, писать файлы, открывать окна и запускать другие процессы.
```

Файл программы на диске и процесс в памяти - не одно и то же.

Файл:

- лежит на диске;
- имеет путь, имя, расширение и размер;
- сам по себе не выполняется.

Процесс:

- уже выполняется;
- находится в RAM;
- получает время CPU;
- имеет права;
- может использовать файлы, сеть, устройства и другие ресурсы.

Эта связь была разобрана в теме [03 Операционная система](<./03 Операционная система.md>): запуск программы означает, что ОС создает процесс на основе файла программы.

### Открыть файл и выполнить файл

Когда пользователь открывает документ `report.docx`, обычно запускается офисная программа, а документ передается ей как данные.

Цепочка:

```text
report.docx -> ОС запускает Word или другую программу -> программа читает документ
```

Когда пользователь запускает `setup.exe`, сам файл является программой:

```text
setup.exe -> ОС создает процесс -> процесс выполняет инструкции установщика
```

Разница важна:

| Действие | Что происходит | Риск |
|---|---|---|
| Открыть `.txt` | Текстовый редактор читает данные | Обычно низкий |
| Открыть `.jpg` | Просмотрщик читает изображение | Обычно низкий, но зависит от программы |
| Запустить `.exe` | ОС запускает программу | Выше |
| Запустить `.bat` | Оболочка выполняет команды | Выше |
| Запустить `.ps1` | PowerShell выполняет сценарий | Выше |
| Запустить `.msi` | Установщик может менять систему | Выше |

Нельзя считать любой документ абсолютно безопасным. Документы сложных форматов могут содержать активное содержимое, например макросы. Но базовая идея остается: выполнение инструкций обычно опаснее, чем чтение обычных данных.

### Программы, скрипты и командные файлы

Программа `.exe` обычно содержит машинный код или код, подготовленный для запуска ОС.

Скрипт - это текстовый файл с командами для другой программы: интерпретатора или командной оболочки.

Примеры:

- `.bat` и `.cmd` выполняются командной оболочкой Windows;
- `.ps1` выполняется PowerShell;
- `.py` выполняется Python, если он установлен;
- `.js` может выполняться разными средами в зависимости от контекста.

Командный файл может выглядеть как обычный текст:

```bat
echo Hello
mkdir backup
copy notes.txt backup\notes.txt
```

Но при запуске это уже не просто текст. Оболочка читает строки как команды и выполняет их по порядку.

Поэтому скрипт может быть опасен не меньше `.exe`. Если в нем есть команда удаления или скачивания, она будет выполнена.

### Установщики

Установщик - программа или пакет, который добавляет программу в систему.

Пакет - это файл или набор данных, подготовленный для установки. В нем обычно описано, какие файлы нужно скопировать, какие настройки изменить, какие ярлыки создать и какие действия выполнить при установке или удалении программы.

То есть установщик может быть самостоятельной программой, которая сама управляет процессом установки, а пакет может содержать инструкции и файлы для специальной системной службы установки.

В Windows часто встречаются:

- `.exe`-установщики;
- `.msi`-пакеты Windows Installer.

Установщик может:

- копировать файлы в `Program Files`;
- создавать папки;
- добавлять записи в меню "Пуск";
- менять настройки;
- добавлять службы;
- устанавливать драйверы;
- добавлять программу в автозагрузку;
- менять переменную `PATH`.

Поэтому установка программ требует осторожности. Установщик часто просит больше прав, чем обычная программа, потому что меняет систему не только для одного файла, а для всего компьютера или пользователя.

### Ярлыки

Ярлык Windows обычно имеет расширение `.lnk`. В проводнике расширение ярлыка часто скрыто.

Ярлык - это не сама программа. Это указатель на другой файл, папку или команду.

Например, ярлык на рабочем столе может указывать на:

```text
C:\Program Files\App\App.exe
```

или запускать программу с аргументами:

```text
App.exe --open lesson.txt
```

Ярлыки удобны, но им тоже нельзя доверять только по иконке. Ярлык может выглядеть как документ, а на самом деле запускать команду или программу.

### Иконка не доказывает тип файла

Иконка - это картинка, которую показывает проводник. Она помогает ориентироваться, но не является доказательством безопасности.

Почему нельзя доверять только иконке:

- разные типы файлов могут иметь похожие иконки;
- вредный файл может использовать знакомую иконку;
- расширения могут быть скрыты;
- файл `photo.jpg.exe` может выглядеть как картинка, если пользователь видит только начало имени;
- ярлык может иметь почти любую иконку.

Надежнее смотреть на полное имя файла, расширение, источник, свойства и контекст.

### Скрытые расширения и двойные расширения

Windows может скрывать расширения известных типов файлов. Тогда пользователь видит:

```text
photo.jpg
```

Но полное имя может быть:

```text
photo.jpg.exe
```

В таком случае настоящее расширение - `.exe`, потому что расширение берется после последней точки.

Примеры подозрительных имен:

```text
photo.jpg.exe
invoice.pdf.exe
homework.docx.bat
archive.zip.cmd
```

Сама по себе двойная точка не всегда означает вредный файл. Например, `report.final.docx` - нормальное имя, где настоящее расширение `.docx`. Но если последняя часть имени - исполняемое расширение, файл требует особой осторожности.

### Права администратора и UAC

Обычная программа запускается с правами текущего пользователя. Она не должна свободно менять системные папки, драйверы и важные настройки.

Права администратора дают программе больше возможностей:

- устанавливать программы для всех пользователей;
- менять системные настройки;
- записывать файлы в защищенные папки;
- устанавливать службы;
- менять драйверы;
- влиять на безопасность системы.

UAC, или User Account Control, - механизм Windows, который спрашивает подтверждение перед действиями с повышенными правами.

Если появляется запрос UAC, это важный сигнал:

```text
Программа просит больше прав, чем обычно.
```

Это не означает, что программа вредная. Установщик известной программы тоже может просить права администратора. Но пользователь должен понимать, какую программу он запускает и зачем ей такие права.

### Что программа может сделать после запуска

После запуска программа получает возможности в пределах своих прав.

Она может:

- читать доступные файлы;
- создавать и изменять файлы;
- удалять файлы;
- открывать окна;
- использовать сеть;
- запускать другие программы;
- читать переменные окружения;
- обращаться к устройствам через ОС;
- добавлять себя или другой файл в автозагрузку, если прав достаточно.

Если программа запущена с правами администратора, круг возможностей шире. Поэтому неизвестный файл с правами администратора особенно опасен.

### Цифровая подпись

Цифровая подпись помогает проверить:

- кто выпустил файл;
- не был ли файл изменен после подписания;
- доверяет ли система издателю или центру сертификации.

В свойствах некоторых файлов Windows можно увидеть вкладку "Цифровые подписи".

Подпись полезна, но не делает файл автоматически безопасным:

- подписанный файл все равно может содержать ошибку;
- издатель может быть неизвестным;
- подпись может быть недействительной или просроченной;
- пользователь может не понимать, почему файл вообще нужно запускать.

Правильная мысль:

```text
цифровая подпись повышает доверие, но не заменяет проверку источника и смысла запуска
```

### Источник файла

Источник файла - место, откуда файл получен.

Примеры источников:

- официальный сайт программы;
- Microsoft Store или другой официальный магазин;
- учебная папка, подготовленная преподавателем;
- ссылка от знакомого;
- вложение в письме;
- неизвестный сайт;
- архив из случайного чата.

Чем менее понятен источник, тем выше риск.

Особенно осторожно нужно относиться к файлам из:

- папки `Downloads`, если непонятно, что именно было скачано;
- писем и сообщений от неизвестных отправителей;
- архивов с непонятным содержимым;
- сайтов с навязчивыми кнопками "Download";
- файлов, которые требуют отключить антивирус или защиту.

### Антивирус и предупреждения Windows

Windows и антивирусные программы могут предупреждать о подозрительных файлах. Такие предупреждения нельзя просто закрывать не читая.

Предупреждение может появиться, если:

- файл скачан из интернета;
- издатель неизвестен;
- файл редко встречается;
- файл похож на вредный;
- программа пытается выполнить опасное действие.

Предупреждение не всегда означает, что файл точно вредный, но оно означает, что запуск требует дополнительной проверки.

### Запуск из командной строки

Программы можно запускать не только двойным щелчком, но и из командной строки.

Пример:

```powershell
notepad
```

PowerShell просит ОС найти программу `notepad` и запустить ее.

Если указать путь:

```powershell
.\tool.exe
```

то запускается файл `tool.exe` из текущей папки. Запись `.\` важна: она явно говорит "взять файл из текущей папки".

Команды тоже требуют осторожности. Если скопировать команду из интернета и выполнить ее, последствия могут быть такими же, как при запуске файла. Команда может скачать файл, удалить данные или изменить настройки.

### Переменная PATH

`PATH` - переменная окружения, в которой перечислены папки для поиска программ. Переменные окружения разобраны в теме [03 Операционная система](<./03 Операционная система.md#окружение-процесса-и-переменные-окружения>).

Когда пользователь вводит команду:

```powershell
python
```

ОС или оболочка ищет программу `python.exe` в папках из PATH.

Для программиста это важно, потому что одна и та же команда может запускать разные файлы, если на компьютере несколько версий программы или PATH настроен по-разному.

На вводном уровне достаточно понимать:

```text
команда без полного пути ищется в специальных папках;
команда с явным путем запускает конкретный файл;
перед запуском неизвестной команды полезно понять, откуда она берется
```

### Типичные ошибки

**"Документ не может быть опасным."**  
Обычный текстовый файл обычно безопаснее программы, но сложные документы могут содержать активное содержимое, ссылки, макросы или использовать уязвимости программ просмотра.

**"Если иконка похожа на PDF, значит это PDF."**  
Нет. Иконку можно подделать, а расширения могут быть скрыты. Нужно смотреть полное имя и свойства файла.

**"Если файл скачан с первого сайта в поиске, ему можно доверять."**  
Нет. В поиске могут быть рекламные или поддельные страницы. Лучше использовать официальный сайт или надежный источник.

**"Если Windows разрешила запуск, файл безопасен."**  
Нет. ОС может предупредить о риске, но окончательное решение часто принимает пользователь.

**"Если программа просит права администратора, нужно просто нажать Да."**  
Нет. Нужно понимать, какая программа просит права и зачем.

**"Скрипт - это просто текст, значит он безопасен."**  
Нет. При запуске скрипт становится набором команд для оболочки или интерпретатора.

## Примеры

### Пример 1. Документ и программа

Файл:

```text
report.docx
```

обычно открывается в офисной программе. Сам документ содержит данные: текст, стили, изображения и служебную информацию.

Файл:

```text
editor.exe
```

запускается как программа. ОС создает процесс, выделяет ему память и начинает выполнение инструкций.

### Пример 2. Установщик

Файл:

```text
setup.exe
```

может установить программу. Он может копировать файлы, менять настройки, добавлять ярлыки и просить права администратора.

Если установщик скачан с официального сайта известной программы, риск ниже. Если он скачан из случайного источника, запускать его опасно.

### Пример 3. Командный файл

Файл `backup.bat` может содержать:

```bat
mkdir backup
copy notes.txt backup\notes.txt
```

Если его запустить, команды выполнятся по порядку: сначала создастся папка, затем файл скопируется.

Если в командном файле будут опасные команды, они тоже выполнятся. Поэтому `.bat` и `.cmd` нужно проверять перед запуском.

### Пример 4. Подозрительное двойное расширение

Файл:

```text
photo.jpg.exe
```

имеет настоящее расширение `.exe`. Часть `.jpg` находится внутри имени и может быть попыткой выглядеть как фотография.

Если расширения скрыты, пользователь может увидеть только:

```text
photo.jpg
```

Поэтому отображение расширений важно для безопасности.

### Пример 5. Ярлык

На рабочем столе есть ярлык:

```text
Game.lnk
```

Он может указывать на:

```text
C:\Games\Game\Game.exe
```

Но ярлык может также запускать команду с аргументами. Поэтому при сомнениях полезно открыть свойства ярлыка и посмотреть поле "Объект".

### Пример 6. Запуск из PowerShell

Команда:

```powershell
notepad notes.txt
```

запускает Блокнот и передает ему файл `notes.txt` как данные.

Команда:

```powershell
.\tool.exe
```

запускает программу `tool.exe` из текущей папки.

В обоих случаях важно понимать, что именно запускается: известная системная программа или неизвестный файл из текущей директории.
